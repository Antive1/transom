# Privacy and data handling

transom is a local desktop program. It has **no telemetry and no analytics**. It makes only these network requests (all HTTPS GET):

- **Update check** (on by default, *Settings > System > Updates*): the list of releases from `api.github.com`, about 90 seconds after
  start and then every 6 hours; when you choose to update, the installer and its checksums from the same GitHub release.
- **Connected calendars** you add yourself (*Settings > Extras*, a private ICS link).
- **Weather** (off by default): the place you choose, to Open-Meteo.

None of these requests carries data about you or your PC beyond what any web request does (your IP address and the user agent
`transom`); nothing transom reads locally is sent anywhere (verified by searching the source for network APIs; this is not a formal audit).

## What transom reads and writes

| What | Where it comes from | When | Where it is written | How to turn it off |
|---|---|---|---|---|
| Media title, artist, state, cover art | Windows media session (GSMTC) | While the media item is shown | Not stored. Shown on the bar only | Hide the *Media* item or start with `--no-media` |
| AI-tool usage (token counts, model ids, timestamps, plan-limit records) | Local logs of Claude Code (`~/.claude/projects`, or `CLAUDE_CONFIG_DIR`) and Codex (`~/.codex/sessions`) | **Only if you enable that source** (all sources are off by default); refresh at most every 5 minutes | Cache `%LOCALAPPDATA%\transom\usage-cache.json` (aggregated numbers, no prompts or file contents) | Disable the source in *Settings > AI and privacy*; *Delete local data* removes the cache |
| Optional daily-totals archive | The same aggregated numbers | Only if you enable the archive (off by default) | `%LOCALAPPDATA%\transom\usage-archive.json` (daily sums per provider and model, no prompts) | Disable it, or use *Delete archive* |
| Claude Code `statusLine` bridge | The data Claude Code passes to its status-line command | Only after you press *Connect Claude Code* | `%LOCALAPPDATA%\transom\claude-statusline.jsonl` (numbers, a session hash and model id) and one added `statusLine` key in `~/.claude/settings.json` | *Disconnect* restores the previous state; *Delete local data* removes the records |
| System audio state | Windows Core Audio: default output name, output list, volume, mute | Only while the *Audio* item is shown and the panel/bar is in use | Not stored; device names are not logged and device IDs are never kept | Hide the *Audio* item |
| Connected calendars (ICS) | Your calendar events, downloaded from the private link you add | Only when a link is added: at start, every 30 minutes and when the calendar opens (stale > 10 min) | The link is kept in transom's settings on this PC, never exported, never logged and shown only as the host name; events are kept only in memory | Remove the calendar in Settings › Extras. |
| Updates | The list of transom releases on GitHub (version numbers and download links); the installer when you choose to update | About 90 s after start and every 6 hours while *Check automatically* is on; *Check now* on request; the download only after you choose *Update now* in the update panel (opened by the notification, the download icon on the bar or *Update to …* in the bar menu). The release notes shown in the panel come from the same list of releases (no extra request) | The installer is saved in `%TEMP%\transom-update\`, its SHA-256 is compared with the release's `SHA256SUMS.txt` and, when the running transom is signed, its signature must come from the same publisher; then it runs and replaces transom (your settings stay) | Turn off *Check automatically* in Settings › System › Updates. Portable copies never install anything: they only open the release page |
| Microphone and camera item | Which apps use the microphone (audio sessions) and camera (Windows privacy history, read-only); microphone mute state | Only while the item is shown or its panel is open | Not stored | Hide the item |
| System monitor item | CPU, memory, GPU and network totals | Only while the item is shown | Not stored | Hide the item |
| Sound profiles | Volume, mute and output of running apps, by program path | When you save a profile | In transom's settings on this PC (program paths and output device IDs); not exported | Delete the profile in the Audio panel |
| App mixer | Windows audio sessions: process ID, program path and file description, session volume and mute, per-app output device | Only while the *Audio* panel is open | Not stored by transom (the per-app output choice is saved by Windows itself); paths, names and device IDs are not logged | Do not open the *Audio* panel; choose *Default output* to clear a per-app output |
| Peripheral batteries | Battery level and charging state of wireless mice, keyboards, headsets and controllers: from Windows for paired Bluetooth devices (the level Windows already shows in *Settings › Bluetooth & devices*); directly from the device for Razer (HID feature reports), Logitech (HID++ 2.0 through the receiver or cable) and NuPhy WH80 (2.4 GHz receiver). Only **read** commands are sent (battery level, charging state, device name); device settings, lighting, firmware and pairing are never touched | While the *Peripheral batteries* item is shown, at the interval you choose (default 60 s) and when you open its panel; never in automated test runs. Only the sources enabled in *Settings › Peripherals* are read | Not stored. Device names and levels are kept in memory only (a device that stops answering is forgotten after 3 minutes); nothing is logged except "service started/stopped" | Hide the *Peripheral batteries* item or switch sources off in *Settings › Peripherals* |
| Shelf | Files you drop on the bar or pick with *Add files…* | Only when you drop or pick; a reference by default, a stored copy only if you choose it. Network locations (UNC, WebDAV, mapped network drives) are kept as references only: transom never probes, copies or drags them out automatically, so an unreachable server cannot stall the other tools | `%LOCALAPPDATA%\transom\tools\shelf\` (paths and optional copies; originals are never modified or deleted; the order you choose is stored in the index) | Remove items, *Settings > Tools > Clear*, or disable the Shelf. The names of the first three Shelf files are also **shown on the bar** (in the middle) while the *Shelf files* item is visible: hide that item in *Settings > Layout* if file names should not be on screen |
| Clipboard history | The clipboard (text, images, file lists as you select) | **Only if you turn it on** (off by default); no polling, a change listener that stops when paused or off; a kind you switch off (text, images, files) is not even read; content flagged private by apps and the **applications you list in *Settings > Tools > Apps never captured*** are skipped (matched by program file name, best effort; not every secret can be detected) | `%LOCALAPPDATA%\transom\tools\clipboard\` **unencrypted**; never logged, synced, uploaded or exported | Turn it off, pause it, delete entries, *Clear* |
| Quick notes | What you type | When you save | `%LOCALAPPDATA%\transom\tools\notes\`; never synced or exported | Delete notes or *Clear* |
| Screenshots library | Image files (PNG, JPG, BMP, GIF, WebP, TIFF) **already saved on this PC** in the Windows Screenshots folder (found through the documented known folder `FOLDERID_Screenshots`, so it follows a redirected Pictures folder) and in folders you add in *Settings > Tools* | Only while the *Screenshots* tab of Tools is open: file names, dates and sizes come from the folder listing; image content is read only to draw the thumbnails of the rows you can see. Not subfolders, never a whole drive; network folders show no previews; online-only (cloud) files are not downloaded | **Nothing is written.** The list and the thumbnails live in memory only (thumbnails are dropped when the tab closes); folder paths you add are stored in `config.json`, never exported. transom only opens an image or its folder; it never moves, renames or deletes a file. While the tab is open the folder is watched with a handle that allows you to rename, move or delete files and the folder meanwhile, and it is released when the tab closes | Turn the library off, remove folders, or turn off the Windows Screenshots folder in *Settings > Tools* |
| Search | Installed apps (shell Apps folder), the Windows Search index (file names only), your note titles and Shelf names; the icons of the results shown (from the Windows shell, by file type or from the app, shortcut target or executable; never from network locations or online-only files) | Only while the search window is used; file contents are never searched; nothing runs until you pick a result; icons are kept in memory only | Not stored. Optional *recent choices* (off by default) keep only the **titles of results you picked** in `%LOCALAPPDATA%\transom\tools\launcher\recent.json` | Leave recent choices off, or disable the sources. The global shortcut (default Alt+Space) is registered with Windows only while the search window is enabled; transom does not watch the keyboard otherwise (no keyboard hook) |
| OLED protection: hiding the bar | The pointer position on screen (`GetCursorPos`) | **Only while the *Hide the bar* option is on**, about 8 times a second, to slide the bar in at the top edge | Not stored or logged | Turn the option off |
| UI sounds | Generated locally (no sound files) | Only if you enable them | Setting only | Disable *UI sounds* |
| Settings | Your choices | On change; on the very first start transom saves the default settings and opens the *Welcome* page | `%APPDATA%\transom\config.json`; before an import the previous file is copied to `%APPDATA%\transom\backups` (last 5) | Delete the files |
| Start with Windows | Your choice in the installer or on the *Welcome* page (Settings › System › Welcome) | When you change it | One value `transom` (the path to `transom-app.exe`) in `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, for your account only | Choose *No* on the Welcome page or turn transom off in Task Manager › Startup apps; uninstalling removes the value |
| Settings export | The allow-listed subset of your settings | Only when you press *Export* | The file you choose | Delete the file |
| Debug log | Diagnostics | **Only** with `--log FILE` | The file you name. It never contains typed characters, note or clipboard text, dropped file paths or search queries (only event kinds, counts and durations) | Do not pass `--log` |

## Things to know

- **`settings.json` backups.** Before connecting the Claude Code bridge transom copies `~/.claude/settings.json` to
  `settings.json.transom-backup-<time>` next to it. Those copies may contain secrets that belong to *other* tools; they are not deleted
  automatically. Remove them yourself when you no longer need them.
- **Config backups** in `%APPDATA%\transom\backups` contain your full configuration, including AI-source switches and display choices
  that the export file leaves out. *Delete local data* does not remove them.
- **Backups of Tools indexes** (`index.json.bak`, kept for crash recovery) are deleted whenever a save removed or changed content (delete, clear, retention, note edit, rename), so removed names and note text do not linger. Orphaned files in transom's own Tools folders (leftover copies, temporary files) are swept on start.
- **What transom writes to the clipboard** (restoring a history item, *Copy text*, copying a Shelf path) is marked with the documented privacy flags `CanIncludeInClipboardHistory = 0` and `CanUploadToCloudClipboard = 0`, so it does not enter Windows clipboard history (Win+V) or the cloud clipboard. If you capture a region with the Windows Snipping Tool (Win+Shift+S), Windows and the tool keep their own copies (including in `Pictures\Screenshots`, which the Screenshots library only lists and opens); transom cannot remove them, and with clipboard history on, an image you copy this way is also recorded like any other clipboard image. Earlier transom builds could save screenshots to `%LOCALAPPDATA%\transom\tools\screenshots\`; that folder is no longer used or deleted, and you can remove it yourself.
- **Debug logs** (`--log`) can contain media titles, application names, window class names and file locations. Do not attach them to
  public issues without removing such details.
- **Exported settings files** never contain AI-source switches, usage data, credentials, local paths, monitor IDs or unknown fields.
  Importing a file shows a preview first and only applies allow-listed fields; it never enables AI sources.
- **Tools data stays out of exports and AI archives.** The export file never contains Shelf, clipboard, notes, screenshot folders, recent searches or
  excluded folders. Files in `tools\` are not encrypted; anyone with access to your Windows account can read them.
- transom never reads credential files (for example `.credentials.json`), conversation contents or prompts.
- The bar needs no elevation and does not run elevated.
